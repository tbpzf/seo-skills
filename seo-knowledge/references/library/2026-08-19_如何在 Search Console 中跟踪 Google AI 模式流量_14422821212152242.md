On 3 June 2026 Google introduced [Search Generative AI performance reports](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports) in Search Console, dedicated views of impressions within generative AI features on Search, such as AI Overviews and AI Mode. At last there’s official AI Overviews reporting showing how often those features involve your pages. What it doesn’t include is the queries behind the AI activity, and the report is UI only. I re-verified on my own property on 11 August 2026 that neither the Search Analytics API nor the BigQuery bulk export exposes the generative AI data, so there’s no official way to track AI Mode traffic at query level.

Except the queries turn up anyway. Fragments of real AI conversations, replies like “yes go on”, follow ups and whole pasted prompts, started appearing as ordinary queries in the performance report. Anastasia Kourou [posted about the strange strings on LinkedIn](https://www.linkedin.com/feed/update/urn:li:activity:7489988920529653761/) and Google’s John Mueller replied, confirming this data had always been available in the performance report and pointing at Google’s documentation.

I’ve written [the full account with sixteen months of my own data](https://suganthan.com/blog/ai-mode-queries-search-console/) separately and deployed my method of extracting these queries via my Google Search Console MCP, so what follows is just the practical ways to pull the AI queries in Search Console out into the open plus a free tool powered by my own custom trained machine learning model that does it for you.

## The scramble for the queries

Once the leak was public, SEOs started building ways to pull those queries out.

The early wave, back in June 2025, was word count regex, surfacing long conversational queries by length alone, anything of 32+ words for example. [Barry Schwartz rounded up those early attempts](https://www.seroundtable.com/conversational-query-data-google-search-console-39550.html), crediting Metehan Yeşilyurt, Vijay Chauhan and David Konitzny. The approaches have got a lot more specific since.

## Method 1. Glenn Gabe’s full inventory in Excel

The performance report UI caps any table at 1,000 rows, so on a big site most of your query data stays hidden before you start. [Glenn Gabe’s answer](https://www.gsqi.com/marketing-blog/how-to-find-ai-mode-queries-gsc/) is to skip the UI. He pulls the complete query set through the Search Analytics API using Analytics Edge in Excel, then has Claude organise the list and flag likely AI Mode queries. If you already live in Excel, this puts the full inventory inside the workflow you know.

![Glenn Gabe's spreadsheet of a site's queries with ranking URL, clicks highlighted at zero, impressions, a category such as chained multi-question query or long form conversational question, likely AI experience AI Mode, confidence and reasoning](https://cdn.suganthan.com/uploads/1786626989643-8bw28.jpeg)

*Glenn's inventory: every conversational query categorised, and a clicks column that reads zero all the way down.*

## Method 2. Jean-Christophe Chouinard’s custom regex

Jean-Christophe Chouinard went after the same problem from inside the report. On 14 August 2026 he [published a regex on LinkedIn](https://www.linkedin.com/posts/jeanchristophechouinard_every-since-barry-shared-that-ai-mode-query-activity-7493679018072887309-GsZz) that flags conversational strings directly in the performance report’s Query filter, using the Custom regex option. He built it by comparing prompts people commonly type into LLMs, from data he has access to, against strings rarely seen in GSC before AI Overviews.

The result is one long alternation covering prompt verbs (write, draft, generate, summarize, explain, act as), greetings, acknowledgements (yes, ok, sounds good, yes go on), refusals and follow ups (more, continue, show me more, any other options). Paste it into the filter and you get an instant look, free, inside the report you already have open.

![LinkedIn post by Jean-Christophe Chouinard sharing a long regular expression for AI Mode queries, covering prompt verbs, greetings, acknowledgements like yes and sure, and follow ups like show me more](https://cdn.suganthan.com/uploads/screendrop-2026-08-17-16-48-39-1-8d1r5.jpg)

Separately, his [12 January 2026 case study](https://www.jcchouinard.com/google-search-console-ai-mode-click-tracking/) showed AI Mode clicks are tracked in Search Console but the queries behind them are almost exclusively anonymised, a caveat that hangs over every method here.

## Method 3. Amin Foroutan’s Advanced GSC Visualizer

[Amin Foroutan’s Advanced GSC Visualizer](https://chromewebstore.google.com/detail/advanced-gsc-visualizer/cdiccpnglfpnclonhpchpaaoigfpieel) is a free Chrome extension that bolts advanced charting, annotations and an AI assistant onto your Search Console data, with one click API access. There’s no AI Mode specific filter in it.

![Promo image for the Advanced GSC Visualizer Chrome extension: one click GSC API access, extract unlimited rows beyond 25,000, with the GSC API Data Explorer interface and the extension popup](https://cdn.suganthan.com/uploads/unnamed-8fb9j.jpg)

## Method 4. My MCP servers

My [Search Console MCP](https://suganthan.com/blog/google-search-console-mcp-server/) has the conversation detector built in as a tool called genai\_conversation\_queries, and my [BigQuery MCP](https://suganthan.com/blog/bigquery-mcp-server/) runs the same detector against the bulk export, which is where the anonymised pool of queries lives. Both run locally, so your data moves only between you and Google. What they do well is automation and scale with query level labels on every row. The limit is setup rather than detection, since you need an MCP client and a config, so they suit technical users.

![genai\_conversation\_queries output, section 1 reply artefacts: yes with 110 impressions and 6 clicks, sure, yes., more, ok, really? and show me, with position and top landing page](https://cdn.suganthan.com/uploads/genai-conversation-queries-8grqn.jpg)

## The four methods side by side

| **Method** | **Strong at** | **Limits** |
| --- | --- | --- |
| Glenn Gabe, API into Excel with Claude | Full query inventory in an Excel workflow | Per run sorting, pattern based |
| Jean-Christophe Chouinard, custom regex | Instant free filter inside the report | English pattern list |
| Amin Foroutan, Advanced GSC Visualizer | Charting and exploring without exports | No AI Mode specific filter |
| My MCPs | Automation and scale, labels on every query | Needs an MCP client and config |

Look down the Limits column and the first three share a gap. Pattern lists and per run sorting can’t reliably catch edge cases like rank tracker probes, agent harness prompts, pasted strings or “my location is” probes. They’re built for English too, so a reply in Tamil or a code mixed Hinglish string sails through unlabelled. Method 4 will solve this problem with a custom ML model.

## Why this needs an ML model

Classifying every query into named buckets, across languages, with the weird machine generated strings included is very hard to do accurately with conventional methods. Because there are so many edge cases etc. So the only reliable way to get this working is to train a machine learning model.

So I decided to build one.

![Terminal log of the classifier training run: two progress bars at 1085 of 1085, then Finished training, saving model, on 12 August 2026](https://cdn.suganthan.com/uploads/hpim6owaaaanovl-8j9q2.jpeg)

## How I built the detector

The detector has two parts. Deterministic rules own the exact classes (reply artefacts, tracker probes, agent harness prompts), and a trained model owns the fuzzy boundary between conversational, long tail and ordinary.

The model is FacebookAI’s xlm-roberta-base, pretrained on 100 languages and fine tuned on my own labelled Search Console conversation exhaust plus synthetic rows across 8 languages, including code mixed Tanglish and Hinglish. I validated it across just over 120k queries scored, and retrained it twice on whatever broke. It runs quantised on a scale to zero Cloudflare container, and the same model now powers a free tool anyone can use without any setup.

## The tool

That tool is the [AI Mode and AI Overview query classifier](https://suganthan.com/free-seo-tools/conversation-query-classifier/), free on this site, and you don’t have to sign up or give me your email.

If the GSC MCP route sounded like effort, this is the same detector with that effort removed.

## How it works

Drop in Search Console or BigQuery query exports as CSV, and several files stack into one run.

![The detector's three steps: drop your Search Console or BigQuery query export, optionally drop the Generative AI report Pages.csv, then Classify and Export CSV, with arrows labelling GSC data and GSC Generative AI report](https://cdn.suganthan.com/uploads/screendrop-2026-08-17-17-02-53-8xb3l.jpg)

**Step 1:** The model will classify your queries into 1 of 7 buckets.

**Step 2:** If you add a Search Console generative AI report, the tool will extract page data and map this against your queries. (In your report, you’ll see an “AI page” column. You’ll see the full URL when you export the CSV)

The deterministic rules label the obvious buckets right in your browser, and those queries never leave your device. I do this because I want to minimise the amount of data I process and to help speed things up.

Everything else goes to the model, gets classified in memory and none of this is stored. Each query comes back with a bucket and a confidence score. In plain words the buckets are full conversational queries, short replies like “yes go on”, follow up pivots like “what about the pro plan”, rank tracker probes, agent harness prompts, pasted strings and ordinary searches. You can filter by bucket, classifier and confidence, then export every labelled row to CSV with no row cap.

## How to use it

Five steps, start to finish.

1. Get your queries out. Under about 1,000 queries the performance report’s normal export is already complete. Bigger sites can stack several filtered exports, pull the full list through the API with Search Analytics for Sheets or Looker Studio, or dump the BigQuery bulk export table to CSV. If you’re an SEO you already know how to get more than 1000 queries off GSC.
2. Drop the CSV or CSVs onto the page.
3. Press Classify.
4. Filter or search the labelled table.
5. Export the labelled CSV.

## Limitations

The tool comfortably handles up to 100,000 unique queries per run in the browser, and a big run needs the tab kept open, which I accept is a very 2010 way to compute. The second limit applies to every way of tracking AI Mode in Google Search Console, mine included. Google anonymises rare queries, conversation strings are rare, and part of the pool never shows, so treat the output results as an undercount. My BigQuery export shows 57.7% of my impressions sat in the anonymised pool over the last 59 days, measured 11 August 2026.
