# Host-reader adaptation

Use this branch when `seo-guest-post` requests a single-content reader brief.
The host publication's readers and editorial purpose determine the useful
angle. Company customers may overlap with them, but a company conversion path
is not the article's default next action.
Apply the [helpful-content standard](../../distinctive-content/references/helpful-content.md) to
the host reader's task.

- Use the parent route's researched contributor guidelines, host audience
  pages, relevant published work, reader comments, and contributor expertise
  as evidence when available. Label inferred reader situations and unchecked
  host fit as hypotheses or unknown.
- Identify the host reader's trigger, current knowledge, decision criteria,
  constraints, next question, expected answer/artifact, completion criterion,
  and proof needed. Return one situation that can support a useful editorial
  thesis, or name the unresolved audience choice.
- Check the host's existing coverage when supplied or requested; otherwise
  record it as unknown. Do not turn this into an owned-site page-gap audit.
- Treat supplied search phrases as clues to reader language. If query evidence
  affects the angle, preserve its sources/context, competing interpretations,
  and uncertainty; the host's audience and editorial remit still set the fit.
  Do not design an owned-site internal-link path or sales CTA for the article.
- Return the evidence-labeled reader situation and validation gaps to
  `seo-guest-post`; that parent checks editorial rules and decides the angle,
  permitted links, disclosure, and submission status.
